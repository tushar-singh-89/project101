# Refactor

Review the current implementation and identify refactorings that materially improve the code.

Do not modify files initially.

Focus on:

* Correctness
* Readability
* Maintainability
* Cohesion
* Coupling
* Duplication
* Extensibility
* Testability

Avoid:

* Unnecessary design patterns
* Premature abstractions
* Over-engineering
* Large rewrites without justification

For every proposed refactoring explain:

1. Current problem
2. Proposed change
3. Why it improves the design
4. Risks/trade-offs

Prioritize changes:

P0 — Required for correctness

P1 — Meaningful design improvement

P2 — Optional cleanup

After presenting the proposed refactoring, wait for approval before modifying files.
