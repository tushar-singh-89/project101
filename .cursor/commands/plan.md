# Plan

Analyze the current problem and codebase.

Do not modify any files.

Provide the following:

## 1. Requirements

Summarize the functional requirements.

## 2. Assumptions

List assumptions that are necessary to proceed.

Identify anything that should be clarified with the interviewer.

## 3. Core Entities

Identify the important classes/entities and their responsibilities.

## 4. Interfaces

Identify interfaces or abstractions that are genuinely useful.

Avoid creating interfaces only for the sake of abstraction.

## 5. Relationships

Explain how the classes interact.

## 6. Main Flows

Describe the important execution flows step by step.

## 7. Edge Cases

List important:

* Invalid inputs
* Empty states
* Boundary conditions
* Failure scenarios
* Duplicate operations
* State transition issues
* Concurrency concerns where relevant

## 8. Design Patterns

Suggest design patterns only where they solve a real problem.

For each proposed pattern explain:

* Why it is needed
* What problem it solves
* What simpler alternative exists

## 9. Test Strategy

List the most important tests.

## 10. Implementation Plan

Break implementation into small incremental steps.

Do not write code yet.

Keep the design simple and appropriate for an interview.
